# Polymath Learning System

The full practical framework for building polymathic breadth and depth simultaneously. Synthesized from the [[5-Hour Rule]], [[Deliberate Practice]], [[T-Shaped Knowledge]], and time management research.

## Phase 1: Foundation Design (Before You Start)

**Step 1: Self-assessment**
- Identify your anchor domain (deepest existing expertise)
- List 10 topics you're curious about
- Identify your learning style and peak focus hours

**Step 2: Select 3–5 target disciplines**
- Choose disciplines that *synergize* — where knowledge in one accelerates the other
- Aim for: 1 technical domain + 1 humanistic domain + 1 meta-skill domain (mathematics, logic, communication)
- Avoid picking too many (~3 is optimal; >5 produces dilettante-level depth)

**Step 3: Define "done" for each discipline**
- Set a mastery threshold before starting: "I am competent in X when I can solve novel problems in X and explain it clearly"
- Simmons's threshold: **top 25%** in each — enough to contribute meaningfully, not enough to exhaust a lifetime

**Recommended discipline combinations**:
| Anchor | Complement 1 | Complement 2 | Result |
|--------|-------------|--------------|--------|
| Engineering | Mathematics | Communication | Research-grade EE polymath |
| Computer Science | Cognitive Science | Design | Human-computer interaction pioneer |
| Medicine | Data Science | Policy | Health systems architect |
| Finance | Psychology | Writing | Behavioral finance communicator |

## Phase 2: Weekly Learning Architecture

**The 5-Hour Rule allocation** (1 hr/day × 5 days):
- **Mon**: Anchor domain (deep work problem set)
- **Tue**: Complement 1 (reading + practice)
- **Wed**: Complement 2 (reading + application)
- **Thu**: Cross-disciplinary synthesis (journaling, connecting ideas, building mental models)
- **Fri**: Wildcard — explore a random domain, read biographies, watch a lecture outside all three domains

**Time of day**: Schedule learning hours during **peak PFC window** (typically morning, first 2–3 hours after waking). See [[Deep Work Scheduling Philosophies]].

**Rotation principle**: Pursue 3–5 topics at a time, rotate every 12–16 weeks. Do not try to do all fields simultaneously every week.

## Phase 3: Core Learning Methods

### Feynman Technique
1. Pick a concept to learn
2. Explain it as if teaching a child — no jargon
3. Identify gaps exposed by the explanation
4. Return to source material, repeat until the explanation is complete

### Spaced Repetition
- Use Anki for vocabulary-heavy domains (languages, medical terminology, historical facts)
- Review intervals: 1 day → 3 days → 7 days → 21 days → 60 days
- Build "intellectual vocabulary" in each domain — the jargon is the framework

### Active Recall
- After each learning session: close the book, write everything you remember
- Far superior to re-reading for retention

### Cross-Domain Journaling
- Weekly prompt: "What did I learn this week that applies to another domain?"
- Explicitly look for the 13 [[Sparks of Genius Thinking Tools]] in your new knowledge

### Nested Learning
- Structure projects to allow simultaneous progress (e.g., build a Python simulation *of* a physics concept = programming + physics simultaneously)

## Phase 4: Output and Synthesis

**Project-based synthesis**: Every 8–12 weeks, create a cross-domain project. The learning loop is: Study → Apply → Synthesize → Teach.

**Teaching as mastery test**: If you can't explain a concept to a curious 15-year-old, you don't know it yet.

**Public synthesis**: Blog posts, GitHub repos, YouTube explanations, or Obsidian notes force synthesis and expose gaps.

## Phase 5: Long-Term Sequencing

| Year | Focus |
|------|-------|
| 1–2 | Anchor domain intensive (vertical bar of the T) |
| 2–3 | First complement intensive + cross-domain synthesis |
| 3–4 | Second complement + talent stack identification |
| 4–5 | Integration: create original work combining all domains |
| 5+ | Output: publish, teach, build — compound the stack |

## Key Mistakes to Avoid

- **Parallelism overload**: Pursuing 8 subjects simultaneously = dilettante in all of them. Cap at 3–5.
- **Passive learning**: Reading without output is slow decay. Every learning session needs a deliverable.
- **Premature jumping**: Switching domains before reaching the top-25% threshold creates surface knowledge.
- **Ignoring the synthesis step**: Breadth without explicit integration is just trivia collection.
- **More research before starting**: The constraint is execution, not information. Start building on Day 1.
