# Worked Examples and Productive Failure

Two complementary, evidence-backed ways to sequence learning and problem solving — and the right one depends on **how much you already know**. (Source: [[Teaching Discipline-Based Problem Solving (CBE-LSE 2022)]])

## Worked examples (the worked-example effect)

For **novices**, studying a fully worked-out solution beats immediately attempting problems. It supplies a model and **cuts extraneous cognitive load**, freeing working memory to build the schema instead of flailing. Best practice:

- Alternate **example → problem pairs** (study one, then try a similar one).
- **Fade** the worked steps as competence grows (do more of it yourself each time).
- Pair with **[[Analogical Encoding (Comparing Cases)|comparison]]** of examples to extract deep structure.

Limit: worked examples mainly buy **near transfer**; over-reliance can leave understanding shallow.

## Productive failure / productive struggle

For learners with **enough prior knowledge**, attempting a hard problem *before* receiving instruction produces deeper, longer-lasting learning — even though short-term performance looks worse. (Kapur 2008; a [[Desirable Difficulties|desirable difficulty]].) The initial struggle activates and differentiates prior knowledge, priming you to absorb the eventual explanation. See [[Productive Struggle]].

## The expertise-reversal rule

> [!tip] One-line rule
> Novice in a topic → **study worked examples first**. Have some footing → **struggle with the problem first, then check the solution.** Match the method to your current level.

The two aren't opposites — a strong routine is: attempt → struggle productively → study the worked solution → compare it to a second example → re-solve from scratch.
